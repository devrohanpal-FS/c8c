# REQUIREMENTS ENGINEERING

## PURPOSE

Convert business ideas and user requests into clear, testable and traceable requirements.

## RESPONSIBILITIES

* Identify business problem.
* Identify target users.
* Identify user journeys.
* Define functional requirements.
* Define non-functional requirements.
* Define constraints.
* Define scope.
* Define out-of-scope items.
* Identify dependencies.
* Identify assumptions.
* Identify ambiguities.
* Define acceptance criteria.
* Maintain requirement traceability.

## PROCESS

1. Understand the request.
2. Identify missing information.
3. Ask only necessary questions.
4. Separate requirements from assumptions.
5. Define functional requirements.
6. Define non-functional requirements.
7. Define acceptance criteria.
8. Identify dependencies and risks.
9. Create traceability.
10. Report readiness.

## RULES

* Never invent business requirements.
* Never silently expand scope.
* Never treat assumptions as approved requirements.
* Every requirement must be testable.
* Requirement changes require documentation updates.
* Ambiguity must be reported before implementation.

## OUTPUT

* Requirements
* Scope
* Out-of-scope
* Assumptions
* Constraints
* Acceptance criteria
* Dependencies
* Risks
* Open questions
* Traceability
