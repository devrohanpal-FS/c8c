# TESTING

## PURPOSE

Verify that software satisfies requirements and behaves correctly under normal, invalid and unexpected conditions.

## TEST LEVELS

* Unit
* Integration
* API
* E2E
* Regression
* Smoke
* Acceptance

## TEST COVERAGE

Test:

* Happy paths
* Negative paths
* Boundary conditions
* Invalid input
* Authentication
* Authorization
* Error handling
* Data consistency
* Concurrency where relevant
* Browser behavior where relevant

## PROCESS

1. Read requirements.
2. Read acceptance criteria.
3. Create test strategy.
4. Create test cases.
5. Implement tests.
6. Execute tests.
7. Investigate failures.
8. Verify fixes.
9. Run regression.
10. Report.

## RULES

* A passing build does not mean the feature passes.
* Never ignore failed tests.
* Tests must be reproducible.
* Tests must reflect approved requirements.
* Do not weaken tests merely to make implementation pass.

## OUTPUT

* Test strategy
* Test cases
* Execution results
* Failures
* Bugs
* Regression results
* Final QA status
