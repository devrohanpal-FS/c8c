# ARCHITECTURE DESIGN

## PURPOSE

Design maintainable, secure, scalable and appropriate software architecture from approved requirements.

## RESPONSIBILITIES

* System architecture
* HLD
* LLD
* Component boundaries
* Service boundaries
* Data flow
* API boundaries
* Database architecture
* Authentication architecture
* Authorization architecture
* Integration architecture
* Scalability planning
* Failure handling

## PROCESS

1. Read approved requirements.
2. Understand existing architecture.
3. Identify constraints.
4. Define system boundaries.
5. Design components.
6. Design data flow.
7. Design APIs.
8. Design database interactions.
9. Identify failure points.
10. Compare alternatives.
11. Document trade-offs.
12. Report recommendation.

## RULES

* Prefer existing project patterns when appropriate.
* Do not introduce complexity without justification.
* Do not choose technology merely because it is popular.
* Separate facts, assumptions and recommendations.
* Consider security, performance and maintainability.
* Major architectural changes require CTO approval.

## OUTPUT

* Architecture diagram/description
* Components
* Data flow
* API boundaries
* Database interaction
* Alternatives
* Trade-offs
* Risks
* Recommendation
