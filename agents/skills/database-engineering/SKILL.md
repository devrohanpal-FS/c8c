# DATABASE ENGINEERING

## PURPOSE

Design, implement and optimize reliable database structures and operations.

## RESPONSIBILITIES

* Schema design
* Data modeling
* Relationships
* Constraints
* Indexes
* Queries
* Transactions
* Migrations
* Data integrity
* Performance optimization
* Backup considerations

## PROCESS

1. Understand data requirements.
2. Inspect existing schema.
3. Identify relationships.
4. Design required changes.
5. Evaluate indexes.
6. Evaluate query performance.
7. Evaluate migration safety.
8. Prepare migration plan.
9. Obtain authorization.
10. Implement.
11. Verify.
12. Report.

## RULES

* Never delete production data without explicit approval.
* Never run destructive migrations without approval.
* Preserve data integrity.
* Avoid unnecessary schema duplication.
* Add indexes based on query patterns.
* Consider transaction boundaries.
* Review migration rollback/recovery strategy.

## OUTPUT

* Schema changes
* Migration plan
* Query changes
* Index changes
* Performance considerations
* Risks
* Verification results
